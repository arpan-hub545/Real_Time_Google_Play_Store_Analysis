1. Abstract

This project presents an interactive analytical dashboard for exploring Google Play Store application data and user reviews.

The system combines Python-based data preparation, exploratory data analysis, Django web development and interactive Plotly visualizations.

The analysis covers application categories, pricing type, ratings, installations, updates, estimated revenue, genres, review sentiment, application size, geographic signals, growth patterns and free-versus-paid application performance.

The dashboard is presented as "Google Play Store Review Analytics" and contains sixteen analytical views designed to transform raw Play Store records into understandable and decision-oriented insights.

2. Introduction

Mobile applications compete for visibility, installations, user engagement and positive ratings. Google Play Store data contains several variables that can be analyzed together to understand the characteristics associated with application popularity and commercial performance.

Instead of restricting the project to a traditional data analysis notebook, this project develops a complete web-based analytical solution.

The system combines dataset preprocessing, exploratory data analysis, feature engineering, sentiment analysis, visualization and web deployment.

3. Problem Statement

Raw Google Play Store data can be difficult to interpret directly because it contains categorical, numerical, textual and date-based attributes.

The project therefore aims to build a single interactive analytical platform capable of cleaning the dataset, calculating useful measures, visualizing relationships and presenting meaningful insights.

Main Analytical Questions

  1. Which app categories are most represented?
  2. What proportion of applications are Free versus Paid?
  3. How are application ratings distributed?
  4. Which categories receive the most installations?
  5. How has application update activity changed over time?
  6. Which categories show greater estimated revenue potential?
  7. Which application genres are most common?
  8. Does application recency influence ratings?
  9. Do Paid apps receive different ratings from Free apps?
  10. What does user-review sentiment indicate?
  11. How do app size, installs, ratings, reviews, geography and monetization interact?

4. Project Objectives

  1. Clean and standardize Google Play Store and user-review datasets.
  2. Perform exploratory data analysis using Pandas and NumPy.
  3. Engineer useful features such as estimated revenue, logarithmic installs, logarithmic reviews, rating groups and year.
  4. Perform sentiment analysis using NLTK VADER.
  5. Merge app-level and review-level information where required.
  6. Create interactive Plotly visualizations.
  7. Deploy the analytical system through Django.
  8. Present meaningful insights alongside every visualization.
  9. Implement time-window-based advanced analytical views.
  10. Interpret findings from data analytics and business perspectives.

5. Dataset and Data Preparation

The project uses two primary CSV datasets.

Dataset Purpose
Play Store Data.csv Contains application-level information including category, installs, reviews, rating, type, price, size and update information.
User Reviews.csv Contains translated application reviews used for review and sentiment analysis.

Data Cleaning

  • Rows without valid ratings are handled.
  • Missing application values are filled where appropriate.
  • Duplicate application records are removed.
  • Ratings are restricted to valid values up to 5.
  • Reviews without translated review text are removed.
  • Installs and Reviews are converted to numerical values.
  • Price information is converted to numeric form.
  • Application size is standardized into MB where possible.

Feature Engineering

  • Logarithmic Install values
  • Logarithmic Review values
  • Estimated Revenue = Price × Installs
  • Year extracted from Last Updated
  • Application Rating Groups
  • VADER sentiment compound score

7. System Architecture

The project follows an analytical web-application pipeline.

Raw CSV Files → Pandas Pre-processing → Feature Engineering → Analytical Aggregation → Plotly Figures → HTML → Django → Web Dashboard

The analytical module processes the datasets and generates Plotly visualizations. Django views pass these generated visualization containers to HTML templates where they are displayed to users.

8. Graphical Analysis and Findings

The dashboard contains sixteen analytical visualizations. The first ten represent the core exploratory analysis while the remaining graphs use additional filtering, transformations, growth analysis, geographical inference and time-based conditions.

Graph 1

Top Categories on the Play Store

A bar chart identifies the ten most frequently occurring application categories.

Finding: Tools, Entertainment and Productivity are among the dominant categories.

Analytical significance: Category concentration helps developers understand highly competitive application segments.
Graph 2

App Type Distribution

A pie chart compares Free and Paid applications.

Finding: Most applications in the dataset are Free.

The result highlights the importance of alternative monetization strategies such as advertisements, subscriptions and in-app purchases.
Graph 3

Rating Distribution

A histogram represents the distribution of application ratings.

Ratings are concentrated toward the higher end of the rating scale, indicating generally favourable user evaluations.

Graph 4

Installs by Category

The visualization calculates total application installations by category.

Finding: Social and Communication applications demonstrate particularly strong installation volumes.

Graph 5

Number of Updates Over the Years

A line chart shows application update activity over time.

The analysis indicates increasing update activity, suggesting continued maintenance and development of applications.

Graph 6

Estimated Revenue by Category

Estimated revenue is calculated using:

Estimated Revenue = Price × Installs

Business and Productivity are highlighted as categories showing strong estimated revenue potential.

Graph 7

Top Genres

Application genres are extracted and counted to identify frequently represented genres.

Finding: Action and Casual are among the most common genres.

Graph 8

Impact of Last Updated on Rating

A scatter plot compares application update dates and user ratings while separating Free and Paid applications.

The relationship appears relatively weak, indicating that recently updated applications do not automatically achieve higher ratings.

Graph 9

Rating for Paid vs Free Apps

A box plot compares rating distributions between Free and Paid applications.

The analysis indicates that Paid applications generally show higher ratings in the dataset.

Graph 10

Sentiment Distribution

User review text is analyzed using the VADER SentimentIntensityAnalyzer.

The review population displays mixed sentiment with a slight positive tendency.

Graph 11

App Size and Average Rating by Installs

This advanced scatter plot examines application size, ratings, installs and categories simultaneously.

Bubble size represents installs while app category is distinguished visually.

The Game category displays strong installation presence within the filtered dataset.

Graph 12

Global App Installs by Category

A choropleth map attempts to visualize installations geographically using country information inferred from application-name keywords.

Important Note: The original dataset does not contain a Country column. Therefore, country information was generated using application-name keywords. As a result, many records remain Unknown and this graph should be interpreted as exploratory geographical analysis rather than actual user-location telemetry.
Graph 13

Total Installs Over Time – 20% Growth

This time-series visualization calculates percentage growth in application installs and focuses on records exceeding 20% growth.

The project identifies strong growth approximately between August 2017 and September 2018.

Graph 14

Cumulative Installs Over Time – 25% Growth

This area chart focuses on highly rated and highly engaged applications and examines cumulative installations over time.

It emphasizes sustained adoption rather than individual one-time changes in installation counts.

Graph 15

Average Rating and Total Review Count

Average ratings and total reviews are normalized to a 0–100 scale to allow the two differently scaled measures to be visually compared.

The graph focuses on selected high-performing application categories.

Graph 16

Average Installs and Average Revenue: Free vs Paid

The final visualization compares average installs and estimated revenue between Free and Paid applications.

It combines audience reach with monetization information and helps determine whether higher adoption and revenue occur under the same business model.

9. Real-Time / Time-Window Feature

Several advanced charts are configured to become available only during particular Indian Standard Time windows.

The application checks the current Asia/Kolkata time before displaying selected advanced visualizations.

If the current time falls outside the configured period, a placeholder visualization informs users about the availability of the analytical insight.

Clarification: The project reads CSV datasets stored with the application. Therefore, the system provides interactive and time-conditioned analysis but does not currently retrieve a continuous live data feed directly from Google Play Store.

11. Key Business Insights

  1. Free applications dominate the dataset, highlighting the importance of alternative monetization methods.
  2. Tools, Entertainment and Productivity are among the most represented categories.
  3. Social and Communication categories show strong installation demand.
  4. Ratings are generally concentrated toward favourable values.
  5. Developer update activity increases across the observed years.
  6. Business and Productivity demonstrate strong estimated revenue potential.
  7. Action and Casual are prominent application genres.
  8. Update recency alone shows only a weak relationship with user ratings.
  9. Paid applications tend to receive higher ratings within the project's comparison.

13. Project Limitations

  1. The datasets are CSV snapshots and are not continuously retrieved from Google Play Store servers.
  2. Estimated revenue uses Price × Installs and does not represent actual realized revenue.
  3. Actual revenue may be affected by taxes, regional pricing, subscriptions, advertising, refunds and promotional activity.
  4. Geographic analysis is inferred from application names rather than actual user-country information.
  5. Several advanced visualizations use highly selective filters and therefore represent subsets rather than the entire dataset.
  6. Time-window availability controls when charts are displayed but does not represent continuous collection of new Play Store data.

15. Conclusion

The Real-Time Google Play Store Analysis project demonstrates how data analytics, visualization, natural language processing and web development can be integrated into a practical decision-support application.

The dashboard transforms Google Play Store application and user-review data into sixteen interactive analyses covering market structure, ratings, installations, updates, estimated revenue, genres, sentiment, geographic signals, growth patterns and monetization.

One of the major conclusions of the analysis is that application performance cannot be explained through a single metric.

Category, application type, installs, reviews, ratings, update activity, app size and user sentiment provide complementary perspectives when evaluating application performance.

The project successfully transforms these dimensions into an accessible Django-based analytical dashboard and provides a foundation for future real-time data integration and predictive analytics.
